# OpenAgent Infrastructure — v0.2.0-alpha.1 Release Notes

> **Release Status**: Alpha Pre-release (Preview / Experimental)  
> **Target Audience**: Early adopters, security researchers, and toolchain testers.  
> **Production Warning**: This pre-release is strictly intended for testing and evaluation. It is NOT approved for production-critical workloads.  
> **Supported Platform**: Linux x86_64 (`x64`) ONLY. Windows and macOS are NOT RUN and unvalidated.

---

## 1. Overview & Major Milestones

OpenAgent Infrastructure `v0.2.0-alpha.1` represents a foundational runtime modernization and dependency vulnerability remediation release. This pre-release transitions the development toolchain to Node.js 22 LTS and modernizes the desktop framework to Electron Modern LTS (`41.10.7`).

### Key Highlights

* **Node.js 22 LTS Runtime Baseline**: Monorepo engines updated to Node.js `>=22.12.0` across all package manifests and CI workflows.
* **Electron Modern LTS (41.10.7)**: Bundled runtime updated to Chromium `146.0.7680.216`, Node.js `24.18.0`, and V8 `14.6.202.34-electron.0`.
* **Zero Vulnerability Dependency Audit**: Completely purged legacy toolchain dependencies (`extract-zip@2.0.1`, `sprintf-js@1.1.3`, `roarr`, and `global-agent`). Both `npm audit` and `npm audit --omit=dev` report 0 vulnerabilities.
  > **Note**: A zero-result dependency audit reflects the absence of known CVEs in the current advisory database and dependency graph; it does not constitute mathematical proof of the absence of all software vulnerabilities.
* **Preserved Defense-in-Depth Security Boundaries**: Strict context isolation, disabled Node integration, renderer sandboxing, allowlisted IPC dispatch, and fail-closed permission handlers remain fully enforced.

## 3. Installation and Verification Instructions (Linux x64)

### Step 1: Verify SHA-256 Checksum

Before extracting or executing the binary, verify the cryptographic hash:

```bash
echo "32195d43211588a35f43c835c0862be32885cd2fcf0c15b3db34f1b0cb4902b7  openagent-desktop-0.2.0-alpha.1-linux-x64.tar.gz" | sha256sum -c -
```

Ensure output is `openagent-desktop-0.2.0-alpha.1-linux-x64.tar.gz: OK`.

### Step 2: Unprivileged Extraction

Extract into a standard user-owned directory without superuser privileges:

```bash
mkdir -p ~/opt/openagent-alpha
tar -xzf openagent-desktop-0.2.0-alpha.1-linux-x64.tar.gz -C ~/opt/openagent-alpha
cd ~/opt/openagent-alpha/openagent-desktop
chmod 0755 openagent-desktop launch-openagent.sh
```

### Step 3: Headless Self-Test

Verify runtime integrity before starting the graphical interface:

```bash
ELECTRON_RUN_AS_NODE=1 ./openagent-desktop -e "console.log('Runtime Self-Test OK: Electron ' + process.versions.electron + ', Node ' + process.versions.node)"
```

Expected output:
```
Runtime Self-Test OK: Electron 41.10.7, Node 24.18.0
```

### Step 4: Application Startup

```bash
./launch-openagent.sh
```

## 4. Data Storage, Vault, and Backup Behavior

* **Data Directory**: Defaults to `~/.config/openagent` (override via `OPENAGENT_DESKTOP_DATA_DIR`).
* **Credential Vault**: AES-256-GCM encrypted local store for API keys and secrets with `0600` permissions.
* **Append-Only Audit Log**: Continuous SHA-256 hash chains with tamper detection.
* **Backup & Verification**: Backup archives are validated against path traversal (`../../`) and payload tampering before restore.

---

## 5. Known Limitations & Scope Boundaries

1. **Platform Restriction**: Strictly Linux x64 only. Windows and macOS builds have NOT been executed or validated.
2. **Headless Execution**: Running the GUI outside a virtual framebuffer (`xvfb`) or active X11/Wayland display will exit or block waiting for a window manager.
3. **Internal Manifest Version**: Internal workspace manifests (`package.json`) currently retain `0.1.0` while the distribution archive is labeled `0.2.0-alpha.1`. A synchronized monorepo version bump is pending project-owner governance approval.

---

## 6. Rollback and Incident Procedures

If any regressions or issues occur with `0.2.0-alpha.1`:
1. Stop running processes: `pkill -TERM openagent-desktop`.
2. Back up user data: `tar -czf ~/openagent-data-backup-$(date +%s).tar.gz -C ~/.config openagent`.
3. Revert to `v0.1.0-rc1` using the historical verified archive (`0fa12457faaf239e1fb5528b906de265d0799301b86e2763e30c100069fca7c4`).
4. Consult [`docs/releases/rollback-and-incident-guide.md`](rollback-and-incident-guide.md) for detailed incident instructions.
